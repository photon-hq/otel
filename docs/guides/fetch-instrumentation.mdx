title: "Fetch instrumentation"
description: "Trace outbound fetch on Bun and Node, propagate W3C trace context, instrument a specific fetch for SDKs, and understand the runtime strategy."
---

`setupOtel()` automatically instruments outbound `fetch` so HTTP requests create client spans and carry trace context downstream. Most services should let setup manage this.

```ts
setupOtel({
  serviceName: "orders-api",
  endpoint: "http://localhost:4318",
});
```

When a traces endpoint is configured, setup instruments fetch by default. The strategy depends on the runtime (see [Runtime strategy and `mode`](#runtime-strategy-and-mode)):

- **Node** uses the official `@opentelemetry/instrumentation-undici` (Node's `fetch` is undici-backed). It captures all undici traffic, emits the full HTTP client semantic conventions, and never monkey-patches the global.
- **Bun** wraps `globalThis.fetch` directly, because Bun's native fetch emits no `diagnostics_channel` events for the standard instrumentations.

The standalone `instrumentFetch()` export always performs the `globalThis.fetch` wrap, and `createInstrumentedFetch()` wraps a single fetch instance (for SDKs) without touching the global.

## What each fetch span contains

For an outbound request, fetch instrumentation creates a span with:

- kind `CLIENT`
- name set to the uppercased HTTP method, such as `GET` or `POST`
- `http.request.method`
- `url.full`
- `server.address`
- `server.port`, when resolvable
- `http.response.status_code`, when a response is received

Statuses (the `globalThis.fetch` wrap — Bun, or `mode: "global"`):

- `2xx` and `3xx` responses are marked `OK`.
- `4xx` and `5xx` responses are marked `ERROR`.
- thrown network errors are recorded as exceptions and marked `ERROR`.

The native undici instrumentation (Node default) follows the HTTP semantic conventions instead: a successful client span is left `UNSET`, and typically only `5xx` and network failures are marked `ERROR`. It also adds richer attributes such as `url.scheme`, `url.path`, `network.peer.*`, and `user_agent.original`.

## Trace propagation

Fetch instrumentation injects the active OpenTelemetry context into outgoing headers using W3C propagation.

That means downstream services receive a `traceparent` header and can continue the same trace.

```ts
await withSpan("orders.enrich", async () => {
  await fetch("https://inventory.example.com/items/sku_123");
});
```

The fetch span becomes a child of `orders.enrich`, and the downstream request receives the trace context.

## Manual instrumentation

You can patch fetch directly:

```ts
import { instrumentFetch } from "@photon-ai/otel";

const instrumentation = instrumentFetch();

await fetch("https://api.example.com");

instrumentation.unpatch();
```

This is useful in tests, custom bootstrap flows, or tools that do not call `setupOtel()`.

## Instrumenting a specific fetch (SDKs)

Sometimes you do not want to touch `globalThis.fetch` — you only want one SDK's outbound calls traced. `createInstrumentedFetch(baseFetch?, options?)` returns a new fetch (client spans + W3C `traceparent` injection) wrapping `baseFetch` (default `globalThis.fetch`, read at call time) without mutating the global. Pass it wherever an SDK accepts a `fetch`:

```ts
import { createInstrumentedFetch } from "@photon-ai/otel";
import OpenAI from "openai";

const client = new OpenAI({
  fetch: createInstrumentedFetch(undefined, {
    attributes: { "peer.service": "openai" },
  }),
});
```

- It returns a fetch function directly. There is no global lifecycle, so no `unpatch()` handle.
- It is idempotent: passing an already-instrumented fetch returns it unchanged.
- `options` accepts `ignore: (url) => boolean` to skip spans for some URLs, and `attributes` to merge static attributes into every span — the practical way to tell different SDKs' spans apart.
- It always uses the wrapper technique, so it behaves identically on Bun and Node. The native undici instrumentation cannot target a single instance.

**Avoid double-counting on Node.** If `setupOtel()`'s global fetch instrumentation is active (the default uses undici, which captures all undici traffic), an SDK request made through a per-instance wrapper is recorded twice — once by the wrapper, once by undici. When you instrument SDKs per-instance, disable the global path with `instrumentFetch: false`, or reserve per-instance wrapping for SDKs you accept doubling on. Bun does not have this problem: its global wrap only affects `globalThis.fetch`, so a separately-passed instrumented fetch is counted once.

## Request and response recording

Fetch spans normally contain only HTTP metadata. Enable recording to export
structured request and response logs linked to each fetch span:

```ts
import { setupOtel } from "@photon-ai/otel";

const otel = setupOtel({
  serviceName: "orders-api",
  endpoint: "http://localhost:4318",
  instrumentFetch: {
    record: { preset: "bounded" },
  },
});

const response = await fetch("https://api.example.com/orders");
await response.text();
await otel.shutdown();
```

The same `record` option works with `instrumentFetch()` and
`createInstrumentedFetch()`. It forces wrapper instrumentation on Node, including
in `mode: "auto"`. Configure an OTLP logs endpoint or an external OTel logger
provider with an exporter: a traces exporter alone cannot deliver these records.

### Choose a preset

Recording is off unless configured. An explicit preset is required; neither
`record: true` nor `record: {}` is accepted.

| Setting | `bounded` | `full` | `custom` |
| --- | --- | --- | --- |
| Body bytes per request/response | 1 MiB | Unlimited | Unlimited |
| Body capture deadline per direction | 30 seconds | Unlimited | Unlimited |
| Concurrent captures per wrapper | 32 fetches | Unlimited | Unlimited |
| Headers | Allowlist | All | All |
| Custom parsers | Rejected | Rejected | Optional |

These are library defaults, not limits prescribed by OpenTelemetry. `custom`
starts with **full**, not bounded, defaults. No preset automatically parses body
content. Override capture settings in any preset:

```ts
record: {
  preset: "full",
  maxBodyBytes: 10 * 1024 * 1024,
  bodyTimeoutMs: 60_000,
  maxConcurrentCaptures: 16,
  headers: ["content-type", "x-request-id"],
}
```

Limits accept nonnegative integers or `Infinity`. A zero byte limit records
metadata without body content; zero concurrency records metadata with a
`capacity_limit` reason. Capacity is shared by calls through one wrapper and
released when the exchange's recording completes. Body deadlines begin when
capture starts for that direction, not when the network request begins.

The bounded header allowlist is `accept`, `content-type`, `content-length`,
`x-request-id`, `traceparent`, and `retry-after`. Header selection is
case-insensitive and applies to both directions. `headers: "all"` explicitly
enables all available headers. Separate `set-cookie` values are retained when
the runtime exposes them. Other repeated headers retain Fetch's combined value.

Selecting `full` or `custom` captures credentials and cookies unless you override
header selection. Existing `redactUrl` is applied to recorded URL fields and
request referrers before parsing or raw fallback. Neither preset automatically
scrubs bodies. OpenTelemetry recommends [explicit header selection](https://opentelemetry.io/docs/specs/semconv/http/http-spans/)
and collecting data deliberately.

### Custom parsers

Only `preset: "custom"` permits `parseRequest`, `parseResponse`,
`parserTimeoutMs`, and `onParserError`. Invalid combinations are rejected by
TypeScript and at runtime before patching fetch.

```ts
import { createInstrumentedFetch, setupOtel } from "@photon-ai/otel";

const otel = setupOtel({
  serviceName: "orders-debug",
  endpoint: "http://localhost:4318",
  instrumentFetch: false,
});

const debugFetch = createInstrumentedFetch(undefined, {
  record: {
    preset: "custom",
    onParserError: "raw",
    parseRequest: (request) => ({ ...request, source: "orders-client" }),
    parseResponse: (response) => {
      const isJson = response.headers["content-type"]?.some(
        (value) => value.includes("application/json")
      );
      if (!isJson || !response.capture.complete || response.body?.encoding !== "utf8") {
        return response;
      }
      return { ...response, parsedBody: JSON.parse(response.body.data) };
    },
  },
});

const response = await debugFetch("https://api.example.com/orders");
await response.text();
await otel.shutdown();
```

Each parser receives a detached snapshot of the **whole record**, including
headers, metadata, body, and capture status. It runs once when its direction
finishes or stops and may return a JSON-compatible value or a promise for one.
The return value replaces the log's `payload`. Returning `null` records a null
payload. Undefined, cycles, non-finite numbers, BigInt, and non-JSON objects are
invalid. Request and response parsers can complete independently and out of order.

`parserTimeoutMs` defaults to 5 seconds; `Infinity` removes the timeout. Timeouts
stop waiting for an asynchronous parser; they cannot interrupt synchronous
JavaScript or cancel the parser's own external work. Parser work runs under OTel
tracing suppression so an instrumented fetch inside a parser does not recurse.

- `onParserError: "raw"` (default) retains the untouched, filtered raw snapshot
  and adds `parserError` and exception details.
- `onParserError: "omit"` omits the payload and exception text, retaining only
  capture/timing metadata and the failure category. Use this when the parser
  removes sensitive content.

Parser mutation cannot corrupt raw fallback or the independent capture status.
Parser errors and recorder errors never replace the application response or
network error.

### Record format

Events `photon.fetch.request` and `photon.fetch.response` have a structured log
body with `schemaVersion: 1`, `direction`, `startedAt`, `finishedAt`, `capture`,
and `payload`. Times are Unix milliseconds. Trace/span IDs are carried in the
standard OTel log context, not inside the replaceable payload.

The default request payload contains `url`, `method`, `headers`, `options`,
`body`, `capture`, `startedAt`, and `finishedAt`. Options include Fetch's standard
cache, credentials, redirect, referrer, integrity, mode, keepalive, and duplex
settings where exposed, plus the initial abort state. Request headers include
injected trace context. `init` method/body overrides are honored, and multipart
capture uses the same serialization sent to the server.

The response payload contains `url`, `status`, `statusText`, `ok`, `redirected`,
`type`, `headers`, `body`, `capture`, `startedAt`, and `finishedAt`.

Bodies are `{ data, encoding: "utf8" | "base64", byteLength }`. UTF-8 is used
only when lossless, including any BOM; otherwise bytes are base64 encoded. An
absent body is `null`, while an empty readable body has zero bytes and empty
`data`. `capture` contains `capturedBytes`, `complete`, and an optional `reason`:
`size_limit`, `timeout`, `capacity_limit`, `abort`, `unavailable_body`,
`read_failure`, or `shutdown`. An exact byte-limit match is complete only after
EOF is observed. Partially captured multibyte characters are preserved as bytes.

On network failure, `photon.fetch.error` carries error details and a timestamp.
Available request evidence is retained; a response record is not fabricated.

Records are emitted directly through the OTel logger with DEBUG severity. They
do not print to the console and are independent of `createLogger()` level
filtering and span sampling. Exporter/backend filtering still applies. Logger
ownership and trace context are captured at fetch start, including in scoped mode.

### Streams, flushing, and limitations

Recording reads cloned bodies independently and returns the original response
without awaiting body reads or parsers. The fetch span still ends when response
headers arrive. Logs are emitted separately when each direction finishes.

Independent cloning may buffer data for a slow or unread application branch and
can continue after the application cancels its branch. Full recording can use
unbounded memory for very large or never-ending streams. For such streams,
choose bounded capture, set explicit limits, or flush when evidence is needed.

`setupOtel().shutdown()` drains pending capture before shutting down exporters.
For standalone instrumentation:

```ts
import { flushFetchRecords } from "@photon-ai/otel";

await flushFetchRecords({ timeoutMs: 5000 });
// Then flush/shut down the OTel providers you own.
```

Flush waits for recordings started before the call. At its deadline it emits
available prefixes marked `shutdown`, stops waiting for parsers, and closes
only the recording branches. The real fetch is not aborted. Responses whose
headers arrive after that recording was stopped are not captured. Calls begun
after flush starts are outside that drain; stop starting work before shutdown.
`timeoutMs: Infinity` waits indefinitely. `unpatch()` restores fetch but does
not itself drain existing recordings.

“Full” means Fetch-visible data. Hidden redirect hops, transport-added headers,
wire framing, and compressed transport bytes may be unavailable. Crashes,
exporter queues, backend size limits, and filtering can still prevent delivery.

## Filtering URLs

Use `ignore` to skip noisy or sensitive requests.

```ts
instrumentFetch({
  ignore: (url) => url.includes("/healthz"),
});
```

When a URL is ignored:

- the original request still runs
- no span is emitted
- no request/response records are emitted
- trace headers are not injected by this wrapper

Use this for health checks or high-volume polling. To keep the span but hide a secret in the URL, reach for `redactUrl` instead (below).

## Redacting URLs

`ignore` drops the whole span. When you want to keep the span but strip a secret from the URL, use `redactUrl` — it rewrites the value stored as `url.full` while leaving `server.address` / `server.port` (derived from the original URL) and the rest of the span intact.

```ts
import { instrumentFetch, sanitizeUrl } from "@photon-ai/otel";

instrumentFetch({
  redactUrl: (url) => sanitizeUrl(url, { params: ["token", "api_key"] }),
});
```

`sanitizeUrl()` follows the OpenTelemetry URL semantic conventions: it replaces sensitive query-parameter values and `user:pass@` credentials with the literal `REDACTED`, keeping the parameter key (`token=REDACTED`). It also redacts a built-in default list (`X-Amz-Signature`, `X-Amz-Credential`, `X-Amz-Security-Token`, `sig`, `X-Goog-Signature`). Pass your own names in `params`, or write any `(url) => string` function for full control — including stripping tokens from path segments.

The redactor only changes what telemetry records; the real request still uses the original URL.

On Node, setting `redactUrl` forces the `globalThis.fetch` wrap instead of the native undici instrumentation (which has no hook to rewrite `url.full`), trading undici's richer attributes for the redaction — the same tradeoff as static `attributes`.

## Automatic OTLP endpoint exclusion

When `setupOtel()` starts fetch instrumentation, it automatically excludes the package's own OTLP trace and log endpoints.

That prevents exporter traffic from tracing itself.

This matters because some runtimes or exporter versions may use fetch internally. Without self-exclusion, telemetry export could recursively create more telemetry.

## Idempotent patching

`instrumentFetch()` is idempotent.

If fetch is already wrapped by this package, a second call does not stack another wrapper.

The implementation uses a global symbol marker to remember the original fetch. That guard works even if two copies of the package are loaded, such as Bun consuming TypeScript source while another path consumes the built ESM bundle.

## Restoring fetch

The returned handle exposes `unpatch()`.

```ts
const handle = instrumentFetch();
handle.unpatch();
```

`unpatch()` restores the original fetch only if the global fetch is still the wrapper this handle installed. That avoids overwriting a later patch installed by other code.

## Request handling details

The wrapper preserves common fetch behavior:

- String and URL input keep `method`, `body`, `headers`, and `signal` from `init`.
- `Request` input keeps existing request headers and merges `init.headers`.
- Already-consumed `Request` bodies are not rebuilt. Headers are mutated in place so trace context can still be injected without trying to recreate an unusable body.
- Extra own properties on the original fetch, such as Bun's `fetch.preconnect`, are copied onto the wrapper.

These details keep instrumentation from changing the request semantics your application depends on.

## Runtime strategy and `mode`

`setupOtel()` picks the fetch strategy by runtime (`instrumentFetch: { mode: "auto" }`, the default):

- **Node** registers the official `@opentelemetry/instrumentation-undici`. It hooks Node's undici at the `diagnostics_channel` level, so it captures all undici traffic — not just `globalThis.fetch` — and emits the full HTTP client semantic conventions. It ships as an optional dependency; if it is not installed, setup falls back to the wrap.
- **Bun** wraps `globalThis.fetch`. Bun's native fetch emits no `diagnostics_channel` events, so undici- and diagnostics-channel-based instrumentations produce no spans there. The wrap is the only mechanism that works.

Pass `mode: "global"` to force the wrap on both runtimes:

```ts
setupOtel({
  serviceName: "orders-api",
  endpoint: "http://localhost:4318",
  instrumentFetch: { mode: "global" },
});
```

Use `"global"` when you want identical spans on Bun and Node, or when you want the wrap's built-in PII scrubbing of error messages applied on Node (the undici instrumentation does not scrub status messages).

Native fetch tracing requires Node 20.6 or newer (the undici instrumentation's floor); older 20.x falls back to the wrap.

## Privacy caveat

Fetch spans include `url.full`, which includes the query string.

Prefer keeping secrets, tokens, emails, and phone numbers out of query strings. When you can't, use [`redactUrl`](#redacting-urls) to strip them while keeping the span, or `ignore` to skip the URL entirely.

Thrown fetch error messages are sanitized before being used as span status messages by the `globalThis.fetch` wrap (Bun, or `mode: "global"`). The native undici instrumentation on Node does not scrub status messages — use `mode: "global"` if you need that scrubbing on Node. Unless you set `redactUrl`, URL attributes are recorded as-is on both paths.

## Best practices

- Prefer automatic setup-managed instrumentation for services.
- Use `ignore` for health checks; use `redactUrl` to strip secrets from traced URLs.
- Keep secrets out of query strings where you can.
- Call `shutdown()` or `unpatch()` in tests to restore global fetch.
- Install setup before code starts making outbound requests.
